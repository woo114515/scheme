# mini-Scheme 解释器挑战

## 1. 任务目标与考察内容

**任务**：与 AI 结对（vibe coding），把本目录的骨架补全为一个符合 `../spec.md` 的 mini-Scheme 解释器，让全部验收测试通过。预计 30 分钟。你不需要会编程——你负责向 AI 描述需求、验证结果、报错时继续迭代。

考察四项：

1. **功能正确**：解释器能否通过全部验收测试（底线）。
2. **模块化**：代码按骨架划分的文件组织，每个文件只做一件事，不把所有代码堆进一个文件。
3. **独立验证**：AI 每改完一步，就运行测试确认，而不是全部写完再测。
4. **迭代能力**：报错时能否描述现象、看懂输出差异、让 AI 修正。

## 2. Scheme 语言简介与模块化思路

### Scheme 是什么

mini-Scheme 是一种极简的编程语言：几乎一切都写成 `(操作符 参数...)` 的形式——操作符写在最前面，括号决定运算顺序。例如 `(+ 1 2)` 表示 1 加 2。完整的语法规则见 `../spec.md`（面向零基础编写，§1 语序必读）。

### 一个解释器怎么运转

解释器就是"读懂一段程序文本，算出结果，再打印出来"的程序。流水线只有三步：

```
程序文本 ──读──→ 表达式 ──算──→ 值 ──打印──→ 结果
```

**模块化**就是把这条流水线拆成职责单一的小模块（本目录里的各个 `.py` 文件）：读的归读的、算的归算的、打印的归打印的。这样每一步都能独立验证——测试挂了，你能立刻知道问题出在哪一步，也知道该让 AI 改哪个文件。

建议自底向上完成：先做"读"（文本变表达式），再做"打印"，最后做"算"（求值），由易到难。

## 3. Autograder 使用方法

在仓库根目录运行：

```
python3 tests/run_tests.py python3 starter/main.py
```

- 它会逐个运行 `tests/cases/` 里的 12 组用例，每组包含一段 mini-Scheme 程序和它的期望输出，逐字节比对。
- `PASS` 表示该组通过；`FAIL` 会打印期望输出与实际输出的差异（`-` 期望、`+` 实际），以及解释器报错时的错误信息。
- 用例从 001 到 012 难度递增。**别一次冲全部**：先让 001 通过，再逐步推进。
- 测试通过 ≠ 结束：打开 `tests/cases/*.scm` 看看程序本身，确认你能讲清楚它为什么是这个输出。
